# Onely Recruiter

Onely（[onely.cc](https://www.onely.cc)，AI 驱动的创作者商业平台）首期情感陪伴业务的 **Operator 招募冲刺原型**：用自动化把「3 天找到、触达并促成 100 名有美区社媒运营经验的 Operator 入驻」从 20 人团队的活压缩到 3 人 + 工具。

四个页面：数据看板 / 线索与导入 / 跟进看板 / 触达文案。技术栈：Next.js 15 + SQLite（Node 内建 `node:sqlite`，零原生依赖）+ 模板文案引擎（可选 AI 润色）。

> 演示数据全部为虚构人物（固定随机种子生成），不含真实个人信息。对外话术统一使用 Onely 官方口径「creator fan-relationship operations（创作者粉丝关系运营）」。

---

## 一、运行方式

**环境要求**：Node ≥ 22.5（`node:sqlite` 无 flag 可用；开发验证于 Node 24）。无需任何数据库服务、无需 API Key。

```bash
npm install
npm run dev          # 开发模式，http://localhost:3777
# 或生产模式
npm run build && npm run start
```

- 首次打开自动灌入 134 条演示线索（覆盖 8 渠道 × 全漏斗状态，时间线分布在 3 天冲刺内）。
- 重置演示数据：页面「线索与导入 → 重置演示数据」，或 `curl -X POST http://localhost:3777/api/seed`。
- 测试：`npm test`（34 个用例：CSV 解析 / 去重 / 评分 / 文案）。
- 接口冒烟：先启动服务，再 `node scripts/smoke.mjs`。
- 页面截图：`node scripts/shots.mjs`（输出到 `demo/shots/`）。

**可选 AI 润色**：触达文案页 →「AI 润色设置」填 OpenAI 兼容中转站的 Base URL / Key / 模型。该调用在**浏览器端直连**，Key 只存本机 localStorage，服务端不发起任意 URL 请求。不配置时全部功能照常可用（模板文案）。

## 二、产品需求（五个模块）

| 模块 | 功能点 | 代码位置 |
|---|---|---|
| 线索导入与去重 | CSV 上传/粘贴导入；三级去重（邮箱 → 社媒号 → 姓名+地区，批内 + 库内）；导入报告（总行数/新增/重复明细）；入库即评分 | `src/lib/csv.ts`、`src/lib/dedup.ts`、`api/leads/import` |
| 筛选与分级 | 满分 100 规则评分：渠道 12 / 美区客户经验 18 / 平台覆盖 15 / 美区班次 15 / 周时长 10 / 英文样题 20 / 聊天经验 7 / CRM 3；A ≥75 直发 Offer、B 55–74 备选、C 淘汰；行内展开评分明细 | `src/lib/scoring.ts` |
| 个性化触达文案 | 渠道模板 × 线索变量（姓名/地区/前两个平台/领域）；D0 首触 / D1 提醒 / D2 最后召集；LinkedIn/OnlineJobs/Upwork 带主题行长信，社群渠道短 DM；批量生成、复制、标记已触达 | `src/lib/copy.ts`、`api/outreach/generate` |
| 跟进状态 | 七阶段看板（新线索→已触达→已回复→已报名→样题完成→已发 Offer→已入驻）+ 淘汰分支；状态推进自动写时间戳；D1 提醒/Offer 催签自动生成跟进排期，逾期标红 | `api/leads/[id]`、`src/app/pipeline` |
| 关键数据统计 | 漏斗（按「到达过该阶段」口径）与逐级转化率；分渠道表现；三日节奏 vs 目标线（34/67/100）；回复率/报名率/样题完成率/Offer 接受率；到期待跟进数 | `src/lib/stats.ts`、`src/app/page.tsx` |

辅助：全量导出 CSV（`/api/leads/export`）、示例导入文件（`public/sample-leads.csv`，含 2 条故意重复用于演示去重）。

## 三、增长方案（3 天 100 人冲刺）

### 目标画像
菲律宾 / 尼日利亚 / 肯尼亚等地、为美欧创作者做社媒代运营的人：能上美区班次、英文书面过关、做过私信互动或社区运营。最热子集是已在做创作者粉丝聊天（chatter）的人——技能完全对口。

### 来源渠道与预期有效线索

| 渠道 | 打法 | 预期线索 |
|---|---|---|
| Telegram/Discord chatter & VA 社群 | 进群发招募，最对口 | ~800 |
| OnlineJobs.ph | PH 最大 VA 简历库，搜 SMM + 发职位 | ~1,500 |
| Facebook 群组 | Filipino VAs / SMM Hub / NG job groups 发帖 + 私戳 | ~1,200 |
| LinkedIn | 搜 PH/NG/KE 的 SMM，档案含美欧客户者 | ~600 |
| X/Twitter | NG 求职圈、bio 关键词 | ~400 |
| Upwork/Fiverr | 公开档案作线索源，站内发职位 | ~300 |
| 转介绍 | 入驻者带人，第 7 天随薪资发推荐奖 | 后期杠杆 |

### 漏斗倒推（演示数据即按此分布）

```
4,000 有效线索 → 触达 3,000 → 回复 600 (20%) → 报名 360 → 样题 250
→ A 级 Offer 140 → 接受 105 → 完成入驻培训 100
```

筛选硬门槛：美区班次、设备+备用网络、周 ≥20h、英文写作样题；能力样题为 3 条脚本化粉丝消息的限时人设回复，LLM 按 rubric 预评分 + 人工抽检 20%。

### 三日排期
- **D1**：建管道、全渠道发职位/进群、首批 2,000 触达（目标入驻 34）
- **D2**：样题海选、第一批 Offer、补触达（累计 67）
- **D3**：滚动补位、全员 Discord 自助入职、首期培训开班（累计 100）

### 入驻后管理 / 培训 / 留存
- **Discord 主阵地**：公告/培训/排班/质检/薪资/闲聊分频道；trainee→operator→senior→lead 角色阶梯；onboarding bot 自助流（验证→读 playbook→quiz→发角色）。
- **Telegram 广播**：PH/NG 到达率高于邮件，公告双发。
- **培训**：D0 playbook（人设库/聊天守则/红线/升级话术）+ 录像；上岗前两轮带评分练习；首班 shadow；每周 coaching。
- **质检**：LLM 全量预评分、低分转人工；响应时长/出勤/评分趋势进仪表盘，任一恶化触发 1v1。
- **留存**：**周结薪资**（Payoneer/Wise，NG 可 USDT）；质量与粉丝留存奖金；阶梯加薪；转介绍奖励。

### 自动化如何降低人工成本

| 环节 | 纯人工 | 本原型 | 节省 |
|---|---|---|---|
| 名单构建与清洗 | 6h/批 | CSV 导入 1min | ~98% |
| 去重 | 2h/批（肉眼） | 三级规则自动 | ~99% |
| 单封触达文案 | 2min/封 | 模板秒级生成 | ~92% |
| 跟进排期/提醒 | 全程人记 | 状态推进自动排 D1/D2 | 100% |
| 样题初筛 | 10min/人 | 规则+LLM 预评分，人工只抽检 20% | ~80% |
| 漏斗统计 | 每日 1h 手工表 | 实时看板 | 100% |

合计：3 天 100 人从「~20 人团队」变为「3 人 + 本工具」；人工只剩三件事——样题抽检、A/B 边界判断、社群里当活人。

## 四、已实现 vs 待验证假设

**已实现（本仓库可复现验证）**
1. CSV 导入 + 三级去重 + 导入报告（`npm test` 34 用例 + `scripts/smoke.mjs` 全绿）。
2. 规则评分与 A/B/C 分级、行内评分明细。
3. 渠道模板 × 变量的个性化文案（D0/D1/D2），批量生成/复制/标记触达。
4. 七阶段跟进看板 + 自动时间戳 + 逾期跟进标红。
5. 漏斗/渠道/三日节奏/转化率实时统计与导出。
6. 可选浏览器端 AI 润色（不配置不影响主流程）。

**待验证假设（需真实投放验证，逐条给验证方法）**
1. 各渠道 20% 回复率 → D1 每渠道各发 200 封测回复率。
2. 样题完成率 70%、Offer 接受率 75% → 首批 50 人真实跑漏斗。
3. OnlineJobs.ph / Facebook 对「创作者粉丝关系运营」口径的接受度 → 先各发 1 帖观察审核与举报。
4. 周结支付通道（Payoneer/Wise/USDT）在 PH/NG 的实际到账体验 → 首批 5 人试发。
5. LLM 样题评分与人工评分一致性 ≥85% → 抽 50 份双评对比。
6. Discord bot 自助入职完成率 ≥90% → 首批入驻实测。
7. 单条 AI 润色成本 < $0.01 → 接中转站后按账单核算。

## 五、安全与合规说明

- 服务端不抓取任意 URL；可选 LLM 调用在浏览器端发起，服务端零 SSRF 面。
- 演示数据为虚构；真实使用时导入文件应来自候选人自愿提交的表单/公开档案。
- 触达遵守渠道规则：站内渠道（Upwork/LinkedIn）以发职位为主，不站外私戳。
